# Human gameplay review — v2.7.5

All game labels remain English. The bidding display shows CURRENT BID and its bidder. Select any higher valid amount through the list or ±5 controls; the explicit Bid amount button is the only action that submits it. Max 250 selects the draft immediately and does not place a bid. Boundary controls disable at the current minimum/250.

At 250, the interface replaces the amount controls with Maximum bid reached, the highest bidder/amount and PASS for each remaining eligible challenger. The confirmed initial-opportunity rule is retained. Equal/lower/over-limit bids remain invalid on the authoritative backend. Drafts are scoped to a hand/turn, and stale form submissions request review instead of silently submitting another amount. Busy-state and server transactions prevent duplicate actions; 30-second auction timeout remains a permanent automatic PASS.

The local hand stays readable during dealing. Table card backs still animate to seats, while the already-visible local faces use a brief brightness effect. Legal moves, card confirmation, trick collection and legitimate partner reveal remain unchanged. Normal bots additionally avoid spending optional trump while a partner has safely secured the trick; follow-suit, cheapest winning trump and private-information limits remain intact.

Verification includes real four-/six-seat Bid 250 browser submissions, unchanged state after selecting Max, double-submit rejection, equal/lower/over-limit rejection, a four-human full game through all phase controls and a six-seat game through visible human controls with server-scheduled bots. Geometry/draft/animation checks cover both modes, small portrait/landscape/desktop viewports and all live phases. Android instrumentation also exercises Max and the maximum state inside the actual bundled WebView. Existing auth, privacy, reconnect, manual/voice scoring and session deletion suites remain release gates.

Disconnect behavior is preserved: a detected seated-human connection loss pauses an active hand. Backgrounding alone does not guarantee an immediate disconnect; ordinary 30-second timers continue while connected. The same identity reopens the active room and uses Reconnect if needed; the existing seat/cards return, then only the admin can Resume when all seated humans are connected. Waiting-list disconnections do not interrupt a live hand. Active-hand replacements remain prohibited; admin may wait or void before replacement. Test data and destructive tests remain emulator-only.

The paused screen now names disconnected players, disables Resume until all seats reconnect, and exposes an owner-only Void hand & replace player action. It asks for confirmation and opens seat management after the existing void transition. Replace with computer is an atomic, server-validated between-hand operation: it removes the outgoing non-admin human, retains their historical identity/scores and creates a distinct ready bot at the same seat with zero initial score. It cannot replace anyone during an active hand or replace the admin. Existing waiting-player assignment remains available. Leave now exits the room view and releases its presence subscription after the accepted leave action, so automatic repair cannot keep the departed view alive.

Starting a fresh hand or receiving an active-hand pause returns clients to the table, closing stale management/history drawers so they cannot cover gameplay or recovery controls.
